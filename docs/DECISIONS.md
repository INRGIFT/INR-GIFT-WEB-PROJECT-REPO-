# Decisions

Short records of choices that shape the code. Newest first.

| Date | Decision | Why | Revisit when |
| --- | --- | --- | --- |
| 2026-10-07 | **SMS second factor behind a build switch** (`NEXT_PUBLIC_SMS_SECOND_FACTOR`, off by default). Off: gate = signed in + confirmed email + password session; no 2Factor.in call, no read of 0007 tables, phone still required at sign-up. | 2Factor.in DLT approval is pending and migration 0007 is not applied; with SMS always on, production sign-up and sign-in would fail for everyone. | DLT approved: apply 0007 and switch on together. |
| 2026-10-07 | **Public access is literally `/` only** (final audit): `/legal/*`, `/support`, `/contact` and `/api/contact` are protected too; robots allows only `/`. | Owner instruction ("Remove any unintended public exceptions such as /legal/*, /support, /contact"). Trade-off: Terms, Privacy and grievance details are not readable before sign-up; owner/legal to confirm. | Owner or counsel asks for public legal pages. |
| 2026-10-07 | (Superseded the same day) Homepage-only public access with `/legal/*`, `/support`, `/contact` public. | Legal pages before consent; IT Rules 2021 grievance details; recovery route. | — |
| 2026-10-07 | **SMS second factor through 2Factor.in, not Supabase MFA.** The verified phone is recorded on `auth.users` (Supabase) by the server after 2Factor matches the code; each session's SMS pass is a server-written `sms_step_ups` row keyed by the Supabase session id; RLS requires it. | Owner chose 2Factor.in as the SMS provider and its own OTP lifecycle. Supabase phone MFA would need Supabase-generated codes (and a paid add-on). | — |
| 2026-10-07 | **Auth email via Supabase Send Email Hook → Resend**, not SMTP. Magic links and invites refused. | One adapter for all INRGIFT mail; passwordless sign-in is not allowed. | — |
| 2026-10-07 | **News provider: NewsData.io** (the owner's "News IO" key), `/api/1/latest` with `X-ACCESS-KEY`. | Confirmed by the owner; endpoints taken from NewsData.io's documentation. | — |
| 2026-10-07 | Production without Supabase runs with sign-in **off**, never demo auth. | A misconfigured deployment must not accept any password. | — |
| 2026-10-07 | Every page renders dynamically (root layout `force-dynamic`). | Access depends on the session; no page may be served from a static or shared cache. | Per-module caching with session-aware keys. |
| 2026-10-07 | GoDaddy receives a source zip (no node_modules, no .next); GoDaddy installs, builds and starts. Build-time tools (TypeScript, Tailwind, PostCSS, type packages) moved to `dependencies`. | The standalone bundle carried node_modules, which collided with GoDaddy's install (npm ENOTEMPTY). `next build` needs those tools even if devDependencies are skipped. | GoDaddy documents a different model. |
| 2026-10-07 | Removed `src/app/(site)/loading.tsx`. | With a route-level Suspense boundary, Next 15 starts streaming before `notFound()` runs, so unknown entities answered 200 instead of 404. Genuine 404s matter more for crawlers and users than a skeleton during client navigation. | Pages move to per-module Suspense streaming (ROADMAP caching item). Add boundaries inside pages, below the point where `notFound()` is decided. |
| 2026-10-07 | `/sitemap.xml` is a hand-written sitemap index over `/sitemap/<section>.xml`. | Next 15 `generateSitemaps` does not serve an index. Both the index and the sections are empty while the site serves demo data, matching robots.txt. | Next serves an index natively. |
| 2026-10-07 | Event and Dataset JSON-LD are deferred. | Calendar events and datasets are generated by DemoProvider. Marking up demo data as real events or datasets would mislead search engines. | A licensed calendar or data source is live. |
| 2026-10-07 | CSP allows `'unsafe-inline'` for scripts and styles. | Next's inline bootstrap and JSON-LD scripts need it without a nonce. A nonce would force every page to render dynamically through middleware. | Pages become static/ISR, or a nonce strategy is adopted. |
| 2026-10-07 | Analytics: our own typed event catalogue, consent-gated, with no vendor. | No vendor was chosen, and the owner must choose one under Indian data-protection rules. Events never carry free text, emails or user ids. | The owner picks a vendor; register it with `setAnalyticsSink`. |
| 2026-10-07 | Content is typed CMS-shaped data in `src/services/content/` with statuses. Only `PUBLISHED` and `UPDATED` are shown. | Allows a headless CMS to be swapped in behind the `content.ts` getters without touching pages. Author is "INRGIFT Research" (an organisation); no people are invented. | A CMS and named reviewers exist. |
| 2026-10-07 | A route registry (`src/lib/route-registry.ts`) is the source of access and indexing rules. | Middleware, robots and tests previously each had their own lists. | — |
| 2026-10-07 | Darker `faint`, `up` and `warn` tokens; inline `.link` always underlined. | Axe colour-contrast and link-in-text-block failures at WCAG AA. | — |
| 2026-10-06 | Market data stays on DemoProvider; the NSE adapter is built but not connected. | No NSE licence or credentials. Endpoints are not invented. | NSE access is granted (`docs/CONNECTORS.md`). |
| 2026-10-06 | (Superseded 2026-10-07) Deployment target is a GoDaddy Node.js app using a standalone `server.js` bundle. | The owner chose GoDaddy for domain and hosting. | Plan type is confirmed (cPanel Node.js or VPS). |
| 2026-10 (earlier) | Hand-written SVG charts and custom primitives; no chart or UI library. | Bundle size, control over accessibility, and a no-new-runtime-dependency rule. | — |
